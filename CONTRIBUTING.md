# Contributing to DAK

Thank you for your interest in contributing to DAK! This document outlines the process for contributing to the public vitrine repository.

## Important Note

**DAK is a commercial product with proprietary source code.** This public repository (`denis0wn/dak`) serves as the marketing vitrine, documentation, and trial distribution point. The actual source code resides in the private repository.

## What You Can Contribute Here

Since the core kernel is proprietary, contributions to this repository are limited to:

- ✅ **Documentation improvements** (README, guides, API docs)
- ✅ **Demo assets** (GIFs, architecture diagrams, example configs)
- ✅ **Blog posts** (technical articles, case studies, tutorials)
- ✅ **Issue reports** (bugs in binaries, documentation errors, trial issues)
- ✅ **Feature requests** (via GitHub Discussions)
- ✅ **Translations** (documentation to other languages)

## What You Cannot Contribute Here

- ❌ Core kernel source code (private repo)
- ❌ Binary modifications (signed releases only)
- ❌ License changes (commercial proprietary license)

## How to Contribute

### 1. Documentation Fixes

1. Fork this repository
2. Make your changes
3. Submit a Pull Request with clear description

### 2. Blog Posts / Technical Articles

1. Create a new GitHub Discussion in "Show and tell" category
2. Or submit a PR adding markdown to `blog/` directory (if created)
3. Topics: Deterministic AI, SOC 2 compliance, audit trails, replay debugging

### 3. Reporting Issues

**For trial/binary issues:** Use the "Trial Request" issue template  
**For documentation bugs:** Open a regular issue with "bug" label  
**For feature requests:** Use GitHub Discussions → "Ideas" category

### 4. Security Issues

**Do NOT report security vulnerabilities via public issues.**  
See [SECURITY.md](SECURITY.md) for responsible disclosure process.
